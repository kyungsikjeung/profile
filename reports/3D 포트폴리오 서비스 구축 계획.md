# 3D 포트폴리오 서비스 구축 계획

## 서비스 개요 및 비전

본 서비스는 크리에이티브 전문가(3D 아티스트, 그래픽/UX 디자이너, 포토그래퍼, 건축가, 콘텐츠 크리에이터)가 자신의 2D 작업 사진을 몇 분 안에 몰입형 3D 포트폴리오로 변환할 수 있는 플랫폼이다. 핵심 가치 제안은 **"사진 업로드 → 3D 변환 → 커스터마이징 → 퍼블리시"** 4단계 플로우로, 기술적 전문성 없이도 완성도 높은 3D 포트폴리오를 만들 수 있다는 점이다. 시장 기회는 명확하다. 포트폴리오 빌더 시장이 **2025년 102억 달러** 규모로 성장하고 있으며, AI 기반 이미지-3D 생성 시장이 **20.4% CAGR**로 급성장하고 있지만, "사진-3D-애니메이션 포트폴리오" 서비스를 제공하는 주요 플레이어는 존재하지 않는다 ([The Insight Partners](https://www.theinsightpartners.com/reports/portfolio-builders-market); [Precedence Research](https://www.precedenceresearch.com/ai-driven-image-to-3d-generator-market)). 특히 한국 시장은 **35만 명의 전문 디자이너**와 **30.5% CAGR의 크리에이터 경제**를 보유하고 있으면서도 3D 포트폴리오 빌더가 완전히 부재한 첫 이자(first-mover) 기회를 제공한다 ([Grand View Research](https://www.grandviewresearch.com/horizon/outlook/creator-economy-market/south-korea)).

## 서비스 기획

### 타겟 사용자

주요 타겟은 **25-40세 크리에이티브 전문가**로, 몰입형 인터랙티브 방식으로 시각적 작업을 어필해야 하는 직군이다. Behance는 **5,000만 명 이상의 등록 회원**, Dribbble은 **195개국 1,600만 명 이상의 사용자**를 보유하고 있으며, 이들 플랫폼은 근본적으로 2D 템플릿 기반으로 동질화된 결과물을 생성한다 ([fueler.io](https://fueler.io/blog/behance-usage-revenue-valuation-growth-statistics); [Wikipedia](https://en.wikipedia.org/wiki/Dribbble)). 사용자 조사에 따르면 **69%의 크리에이티브 전문가가 지난 12개월 내 번아웃을 경험**했으며, 이는 차별화된 포트폴리오에 대한 절실한 수요로 이어진다 ([Creative Boom](https://www.creativeboom.com/news/the-state-of-the-creative-industry-2026-what-our-survey-tells-us-about-money-burnout-and-ai)). 결제 의증은 이미 확립되어 있다. ArtStation Pro는 **월 $9.95**, Behance Pro은 **월 $9.99**, Squarespace는 **월 $16-99**에 판매되고 있으며, 프리미엄 3D 포트폴리오 서비스는 **월 $19-39** 가격대에서 방어 가능한 포지셔닝을 가진다 ([ArtStation](https://www.artstation.com/about/artists/portfolio); [Squarespace](https://www.squarespace.com/pricing)).

### 핵심 기능 정의

**Must Have (MVP):** 사진 업로드 및 품질 가이드, AI 기반 3D 변환(단일 이미지), 기본 3D 뷰어(회전/줌), 3-5개 스타터 템플릿, 기본 커스터마이징(색상/텍스트/레이아웃), 공유 가능한 URL로 퍼블리시, 모바일 반응형 출력, 사용자 인증(이메일 + 소셜 로그인), 무료 티어(월 3회 변환). **Should Have (Post-MPV):** 멀티뷰 이미지 업로드, AI 배경 제거, 도메인 연결, 기본 분석(조회수/공유), 프리미엄 템플릿 마켓플레이스, GLB/USDZ보내기, 한국어 지원 및 로컬 로그인(Kakao/Naver). **Could Have (V2):** 커리어 애니메이션(스크롤 기반 장면), 고급 커스터마이징(조명/카메라 경로/오디오), 팀 협업, API 액세스, 화이트라벨, 벌크 처리. **Won't Have (연기):** 풀 3D 씬 에디터, 실시간 다자 협업, 네이티브 모바일 앱, AR/VR 보기, 텍스트-3D 생성, 3D 에셋 마켓플레이스.

### 수익 모델

**하이브리드 구독 + 크레딧 기반 가격 정책**을 채택한다. 무료 티어(3개 프로젝트, 워터마크, 월 5회 AI 변환) → Pro(월 $19, 무제한 프로젝트, 워터마크 제거, 월 20회 변환, 커스텀 도메인) → Studio(월 $39, 월 100회 변환, 우선 렌더링, 팀 협업, 분석) → Enterprise(커스텀, 무제한 변환, SLA, 화이트라벨, API). 하이브리드 가격 모델을 사용하는 기업은 **38% 높은 매출 성장률과 38% 높은 순매출 유지율**을 보고하며, 1 credit = 1 output 단순 원칙을 따른다 ([Chargebee 2025 State of Subscriptions](https://www.saasmag.com/hybrid-pricing-saas-growth-2026/)). 연간 결제 시 **20% 할인**은 업계 표준이다. 5% 월간 이탈률 기준 LTV는 **약 $380**, 3% 이탈률 시 **약 $633**이며, LTV:CAC ≥ **3:1** 목표이다.

### 시장 진출 전략

한국 시장을 우선 타겟으로 하며, **API-first 아키텍처(Meshy/Tripo)**로 시작하여 월 5,000개 모델 이상 시 자체 호스팅(Hunyuan3D/TRELLIS.2)으로 전환한다. 코어 비용 구조: API 호출당 **$0.18-0.25**, 자체 호스팅 시 GPU 비용이 **50-100x 절감**된다 ([HackerNoon benchmark](https://hackernoon.com/how-i-stress-tested-3-ai-3d-generators-on-the-same-inputs-what-the-numbers-actually-show)). 마케팅은 **크리에이티브 커뮤니티 바이럴**("크리에이터가 크리에이터를 복사하는" 루프)과 **SEO**("3D 포트폴리오", "인터랙티브 포트폴리오 웹사이트" 고의도 키워드, CAC $70-120)를 우선 활용하고, 유료 획득(Google Ads CAC $200-350)은 상위 티어에 제한적으로 적용한다. 한국 시장 진출 시 Naver 검색, KakaoTalk 채널, 로컬 결제 게이트웨이(Toss Payments, Naver Pay, KakaoPay)는 출시 일부터 통합해야 한다.

## UX 플로우

### 사용자 여정 설계

최적 사용자 여정은 **"5분 내 첫 가치 달성"** 원칙을 따른다. 온보딩 깔때기는 Signup → First Value(Aha Moment) → Activation → Habit → Conversion 순서로 구성되며, First Value는 **1-5분 내**, Activation은 **1-3일 내** 달성을 목표로 한다 ([uxerwave.com](https://uxerwave.com/grow-your-creator-tool/saas-onboarding-best-practices/)). 구체적 플로우: 랜딩 → 데모 3D 변환 체험(가입 불필요) → 회원가입 → 첫 사진 업로드 → 3D 결과 확인(Aha Moment) → 커스터마이징 → 퍼블리시. 가입 전 체험 패턴은 3D 변환 도구에 특히 적합한데, 핵심 가치(사진이 3D로 변하는 것)가 시각적으로 설득력 있고 자기 설명적이기 때문이다. 각 단계는 **인지 부하의 급격한 점프를 피하는 점진적 공개(progressive disclosure)**로 설계하며, 다단계 폼은 **3-5단계로 제한**하고 진행 상태를 처음부터 표시한다 ([wearetenet.com](https://www.wearetenet.com/thoughts/how-tenet-approach-ux-for-multi-step-workflows)).

### 온보딩 및 활성화

활성화 지표는 **"사용자가 사진을 업로드하고 첫 3D 모델을 수신하는 것"**으로 정의한다. 온보딩은 다음 순서로 구성된다: 회원가입 → "주요 목표가 무엇인가?"(1-3개 옵션: 취업/클라이언트 획득/개인 브랜딩) → 예시 3D 포트폴리오가 미리 채워진 워크스페이스 → 첫 사진 업로드 → 3D 결과 확인 → 커스터마이징 → 퍼블리시. 활성화 체크리스트는 **5개 항목 이하**로 제한: (1) 사진 업로드, (2) 3D 결과 확인, (3) 템플릿 선택, (4) 씬 커스터마이징, (5) 포트폴리오 퍼블리시. 체크리스트는 자동 완료 감지(사용자가 "프로젝트 만들기"를 클릭하면 1단계가 자동 완료로 표시)를 적용하며, 컨텍스트 툴팁은 모달 투어 대비 **3-5x 높은 활성화 리프트**를 보인다 ([vibeweek.ai](https://www.vibeweek.ai/grow/onboarding-tour-implementation-chat)). 업그레이드 프롬프트는 타이머 기반이 아니라 **이벤트 기반**으로 발동: 무료 변환 한도 도달, 프리미엄 템플릿 클릭, 워터마크 제거 시도 시. 업그레이드 프롬프트는 가치 해제 프레임("무제한 프로젝트 생성을 위해 업그레이드")을 사용하고, 제한 강제 프레임("무료 플랜 한도에 도달했습니다")은 피한다 ([ivanhub.co.uk](https://ivanhub.co.uk/insights/saas-freemium-conversion-optimisation-framework-2026)).

### 3D 변환 워크플로우

비기술 사용자를 위한 워크플로우는 **업로드 → 생성 → 커스터마이징 → 퍼블리시** 4단계로 추상화되며, AI가 배경 제거, 깊이 추정, 메시 생성을 자동 처리한다. 입력 품질 가이드는 사전 예방적으로 제공한다: 좋은 예시 사진 표시, 실시간 이미지 품질 피드백(해상도, 배경 복잡도, 조명), 원클릭 AI 배경 제거. 생성 과정은 진행 상태와 함께 무엇이 일어나고 있는지 설명하는 교육적 콘텐츠(깊이 추정, 메시 생성, 텍스처링)를 표시하여 신뢰를 구축하고 기대를 관리한다. 퍼블리시 전 검토 단계는 필수적이며, 사용자는 3D 모델을 회전하고 아티팩트를 확인하고 불만족 시 재생성할 수 있어야 한다. 한국 사용자를 위해 모바일 우선, 하단 고정 액션, 간결한 CTA(-하기 형식), 로컬 로그인(Kakao, Naver, Toss) 지원이 필수다 ([localazy.com](https://localazy.com/blog/korean-ux-localization-for-your-app-guide)).

### 커리어 애니메이션

커리어 애니메이션은 퍼블리시 후 정적 3D 포트폴리오를 내러티브 경험으로 변환하는 기능으로, Pro 또는 Studio 티어에서 제공한다. 구현은 템플릿 기반으로, 사용자는 커리어 스토리 아크("성장 스토리", "프로젝트 쇼케이스", "스킬 저니")를 선택하면 시스템이 적절한 카메라 경로, 전환, 타이밍을 자동 생성한다. 사용자는 실시간으로 애니메이션을 미리보고 페이싱을 조정할 수 있지만, 키프레임 애니메이션이나 타임라인 편집 지식은 필요하지 않다. 이 기능은 2026년 수상 3D 사이트에서 지배적인 "스크롤을 스토리텔링 엔진으로" 패턴에 매핑되며, 한국 사용자의 높은 모션 애니메이션 선호도와도 부합한다 ([utsubo.com](https://www.utsubo.com/blog/best-threejs-websites-2026)).

## 디자인 시스템

### 디자인 방향성

2026년 포트폴리오 디자인은 **절제(Abundance over Restraint)**를 지향하며, 하나의 강력한 시각적 개념을 정밀하게 실행하고, 스크롤 기반 스토리텔링, 모바일 우선 아키텍처, 목적에 맞는 3D를 강조한다. "파티클 필드 히어로 + 회전 로고" 패턴은 과포화 상태이며, 차별화는 개념과 장인정신에서 나온다 ([svilenkovic.com](https://svilenkovic.com/3d/3d-portfolio-trends-2026)). 서비스는 두 가지 미학적 방향을 지원한다: **"Korean Minimal"**(깔끔, 모바일 우선, 정보 밀집, 명확한 계층)과 **"Global Premium"**(미니멀, 공간 중심, 3D 포워드, 다크 모드, 커스텀 타이포그래피). 한국 미학은 대담한 색상 액센트, 장난기 있는 마이크로 애니메이션, 글래스모피즘, 높은 정보 밀도를 포함하고, 글로벌 미학은 절제, 네거티브 스페이스, 단일 3D 히어로 모먼트, 커스텀 타이포그래피, 다크 모드를 포함한다 ([vocal.media](https://vocal.media/01/why-korean-web-design-feels-so-different); [vistaprint.com](https://www.vistaprint.com/hub/web-design-trends-2026)).

### 3D 통합 원칙

지배적인 2026 패턴은 **하이브리드 2D/3D**다. 선명한 2D 타이포그래피와 UI가 풍부한 3D 배경 위에 레이어링되며, 하나의 강력한 3D 모먼트를 정밀하게 실행하는 것이 열 개의 장식적 3D보다 낫다. 3D는 항상 명확한 커뮤니케이션 목적(제품 시각화, 공간 스토리텔링, 내비게이션 구성)을 가져야 하며, 장식 자체가 되어서는 안 된다. 서비스는 **"3D 예산"**을 적용한다: 최대 1개의 히어로 3D 씬, 섹션당 1개의 인터랙티브 3D 요소, 미묘한 깊이를 위한 CSS 3D. 기기 등급 감지 시스템이 엔진에 내장되어야 하며, 고사양은 풀 3D, 중간은 간소화, 저사양은 정적 폴백을 제공한다. 점진적 향상(progressive enhancement)은 선택이 아닌 필수다: 정적 이미지 → 저폴리곤 → 풀 3D ([designdeluxe.in](https://designdeluxe.in/3d-website-design-trends-2026/); [cidcreative.com](https://www.cidcreative.com/insights/immersive-3d-interfaces-web-brand-experiences/)).

### 토큰 아키텍처

3계층 토큰 시스템을 구축한다: **Foundation(Primitive) → Core(Semantic, 테마 적응) → Component-specific**. 토큰 네이밍은 Foundation → Property → Modifier 규칙을 따른다 (예: `color.text.hover`). 색상 토큰은 primary, secondary, tertiary, neutral, surface, onSurface, error를 포함하고, 타이포그래피 토큰은 headline-display부터 label-sm까지 9-15 레벨을 정의한다. 간격은 8px 그리드(xs 4px, sm 8px, md 16px, lg 32px, xl 64px, gutter 24px, margin 32px)를 사용한다. 3D 특화 토큰으로 perspective(1000px), parallax-layers(5), animation-duration(300-400ms), shadow-depth(20-40%)를 정의한다. 모션 토큰은 spring stiffness 120, damping 20, entry 540ms ease-out, hover 200ms, page transition 300ms를 기본값으로 사용한다. 테마는 CSS 커스텀 프로퍼티로 구현하며, `data-theme="dark"`로 다크 모드를 제어하고, 컴포넌트 변경 없이 미학적 방향 전환이 가능하다 ([SAP Design System](https://www.sap.com/design-system/digital/foundations/tokens/design-tokens/); [Atlassian Design](https://atlassian.design/tokens/design-tokens); [designmd.app](https://designmd.app/library/3d-hyperrealism)).

### 컴포넌트 라이브러리

**50개 이상의 React 컴포넌트**를 구축하며, 포트폴리오 특화 컴포넌트(ProjectCard, CaseStudyLayout, SkillVisualization, TechStackVisualizer, WorkExperience, EducationTimeline)가 차별화 포인트다. 기본 컴포넌트는 Accordion, Alert, Avatar, Badge, Button, Card, Carousel, Dropdown, Input, Navigation, Tabs, Timeline, Toast, Toggle, Tooltip을 포함한다. 모든 상태 기반 컴포넌트는 5가지 상태 역할(info, positive, warning, error, neutral)을 공유한다. 깊이는 토큰 소유이며, 컨테이너 램프와 elevation 토큰으로 관리하고 컴포넌트가 자체 그림자를 가져가지 않는다. WebGL 앰비언트 배경은 런타임에 시맨틱 색상 토큰을 읽어 3D를 디자인 시스템과 연결하는 프리미엄 기능으로 제공한다 ([robr0 design-system](https://github.com/robritacca-dotcom/design-system); [ehsanpo/design-system](https://github.com/ehsanpo/design-system)).

### 마이크로 인터랙션

마이크로 인터랙션은 피드백과 웨이파인딩 역할을 수행한다. 핵심 패턴: 호버 시 스프링 댐프 틸트, 스크롤 기반 카메라 이징, 셰이더 기반 전환 효과, 컬러 필 어포던스 리브, 성취/배지 시스템. 모든 마이크로 인터랙션은 **trigger → rules → feedback → loops** 구조를 따르며, `prefers-reduced-motion`을 존중하고 정적 대안을 제공한다. 2D 컨트롤은 최소 **44x44px** 터치 타겟을 유지하고, 키보드 접근 가능한 패널을 제공한다. 스프링 물리(stiffness 120, damping 20)가 기본 애니메이션 곡선이며, 스케치-투-컬러 호버 패턴은 시그니처 인터랙션으로 제공한다 ([Toptal](https://www.toptal.com/designers/product-design/microinteractions-better-ux); [dotpingdesign.com](https://dotpingdesign.com/interactive-glb-react-pixal3d-3d-ui/)).

### 성능 및 접근성

성능은 3D 포트폴리오의 성패를 가르는 요소다. 표준 아키텍처는 **islands/partial hydration, Three.js 동적 임포트, 기기 등급 감지, 적응형 품질 스케일링, 완전한 2D 폴백**이다. Astro v5 island 아키텍처는 1MB Three.js 번들이 3D 페이지만 로드되어 Lighthouse 100/100 SEO를 달성한 사례가 있다 ([aniruddhatrey.com](https://www.aniruddhatrey.com/blog/architecture-behind-3d-portfolio)). 성능 예산을 적용한다: 초기 3D 에셋 **<2MB**, 중간 모바일에서 **30fps 이상**, 드로콜 **데스크톱 <100, 모바일 <50**. `compileAsync` + `KHR_parallel_shader_compile`은 TBT를 7.95초에서 약 2.0초로 단축시킨다. 모든 3D 요소는 시맨틱 HTML 대안, 키보드 내비게이션, `prefers-reduced-motion` 지원을 가져야 하며, `?no3d=1` URL 파라미터로 테스트 및 사용자 제어를 지원한다 ([simplified.media](https://simplified.media/guides/webgl-threejs); [dev.to/jonasjavier](https://dev.to/jonasjavier/a-3d-portfolio-google-can-read-and-a-phone-can-run-2jlo)).

## 기술 아키텍처

### 기술 스택

**프론트엔드:** Next.js 16 App Router + React 19 + Three.js + React Three Fiber(R3F) + Drei + GSAP + Lenis + Tailwind CSS v4. R3F는 React 기반 Three.js 작업의 지배적 패턴이며, GSAP + Lenis는 스크롤 기반 애니메이션을 처리한다. **백엔드:** Python FastAPI + Pydantic + Uvicorn. 3D 생성 모델의 PyTorch/TensorFlow 생태계를 활용하기 위해 Python 기반이다. **AI 추론:** 클라우드 GPU 인스턴스(L4/A100)에서 Hunyuan3D/TRELLIS 실행. **스토리지:** S3/GCS + CDN. **형식:** GLB (glTF 2.0) + Draco 메시 압축 + KTX2 텍스처 압축. 이 스택은 성능, 개발자 생태계 성숙도, 배포 유연성의 균형을 제공한다 ([creativedevjobs.com](https://www.creativedevjobs.com/blog/how-to-hire-a-threejs-developer); [Tencent-Hunyuan/Hunyuan3D-2.1](https://github.com/Tencent-Hunyuan/Hunyuan3D-2.1/blob/main/api_server.py)).

### 3D 변환 파이프라인

비동기 마이크로서비스 아키텍처로 구성한다: **API Gateway → Job Queue(Redis/PubSub) → GPU Worker Pool(Hunyuan3D/TRELLIS) → Object Storage(S3/GCS) → CDN Delivery**. 각 단계는 수요에 따라 독립적으로 스케일링된다. 3D 생성 요청은 동기적으로 처리할 수 없다. 단일 고폴리곤 모델은 **30-60초**가 소요되므로, 클라이언트가 요청을 포스트하면 서비스가 즉시 job ID를 반환하고 클라이언트가 상태를 폴링하는 비동기 패턴을 적용한다 ([tencentcloud.com](https://www.tencentcloud.com/techpedia/146781)). 파이프라인은 생성적 경로(Hunyuan3D, 단일 이미지)와 사진측량 경로(VGGT/2DGS, 다중 이미지)를 모두 지원한다. GPU 워커는 세마포 기반 동시성 제어(예: limit_model_concurrency=5)로 OOM을 방지하고, 모델 로딩/언로딩은 온디맨드로 최적화한다. 작업 테이블(Redis 또는 SQL)은 상태 전이를 추적하여 크래시된 워커가 재개할 수 있게 한다.

### 3D 에셋 최적화 및 전달

GLB를 기본 형식으로 사용하며, Draco 메시 압축 + KTX2 텍스처 압축으로 **90-95% 파일 크기 감소**를 달성한다. Draco는 메시 파일을 **70-90%** 압축하고, KTX2/Basis Universal은 텍스처를 **70-90%** 압축하며 GPU 메모리에서도 압축 상태를 유지한다(4K 텍스처 기준 64MB → 약 4MB). 최적화 파이프라인은 빌드 타임에 gltf-transform/gltfpack으로 실행한다: raw mesh → decimation → Draco → KTX2 → GLB export. 스토리지는 3계층 전략을 사용한다: hot storage(최근 생성, CDN 캐시) → warm storage(S3 standard) → cold storage(S3 glacier, 미사용 에셋). 클라이언트 로딩은 GLTFLoader + DRACOLoader + KTX2Loader를 구성하고, 디코더 실패 시 미압축 GLB로 폴백한다 ([docs.unity.com](https://docs.unity.com/asset-transformer-sdk/2026.1/manual/sdktips/export-guidelines); [hontran.dev](https://www.hontran.dev/blog/three-js-performance-optimization)).

### 실시간 렌더링 최적화

핵심 과제는 드로콜 예산 관리(데스크톱 <100, 모바일 <50), 텍스처 메모리 최적화(KTX2), 모바일 GPU 열 스로틀링, 60 FPS 유지다. 해결책: **InstancedMesh**(수천 개의 복사본을 1개 드로콜로 렌더링), **frameloop="demand"**(정적/스크롤 기반 씬에서 유휴 GPU 사용량을 0에 수렴), **DPR 상한 2x**(3x는 9x 픽셀 필), **적응형 DPR**(FPS 45 미만이면 0.75로 다운그레이드, 55+ 안정 시 1.5로 상향), **동적 컬링**(카메라 프러스텀 밖 요소 적극적 제거). Three.js는 GPU 리소스를 자동으로 가비지 컬렉션하지 않으므로, 해제되지 않은 geometry/material/texture은 VRAM을 누수하여 컨텍스트 크래시를 유발한다. 렌더링 루프는 비활성 상태와 탭 전환 시 자동 일시정지해야 한다 ([simplified.media](https://simplified.media/guides/webgl-threejs); [tympanus.net](https://tympanus.net/codrops/2026/04/28/more-than-a-portfolio-building-a-scroll-driven-3d-world-with-something-to-say/)).

### 인프라 비용 구조

GPU 비용이 지배적이다. MVP 규모(일 100회 생성)는 스팟 L4 인스턴스로 **일 $50-100**, 대규모(일 10,000+ 생성)는 H100/A100 클러스터로 **일 $2,000-5,000**이 필요하다. 스토리지와 CDN 비용은 이차적이지만 사용자 기반에 따라 선형적으로 증가한다. 클라우드 GPU 가격(2026): L4 **$0.44-0.80/hr**, A100 80GB **$0.68-5.03/hr**, H100 80GB **$1.49-6.98/hr**. 전략적 접근: MVP 단계는 호스팅 API(Tencent Hunyuan3D, 약 $0.05-0.20/생성)로 시작하여 GPU 인프라 투자를 회피하고, 성장 단계에서 자체 호스팅 스팟 인스턴스로 전환하여 생성당 비용을 **50-100x 절감**한다. 스토리지는 최적화된 GLB당 약 5-20MB이므로 10,000개 모델 = 50-200GB = S3 standard로 월 $5-20이다 ([cloudzero.com](https://www.cloudzero.com/blog/cloud-gpu-pricing-comparison/)).

### 기술 리스크 및 완화

최우선 리스크는 **GPU 비용 폭증**이다. 완화: 호스팅 API로 시작, 성장 단계에서 자체 호스팅 스팟 인스턴스로 전환, 런당 비용 상한 설정. 두 번째는 **모델 품질 불일치**다. AI 생성 모델은 유리, 거울, 크롬, 가는 선/머리카락, 빈 내부, 심한 가림 등에서 품질이 저하된다. 완화: 품질 스코어링(메시 무결성, 텍스처 커버리지), 저품질 시 자동 재생성, 사용자 피드백 루프. 세 번째는 **브라우저 호환성/성능 파편화**다. WebGPU는 2026년 초 기준 Safari/Firefox 지원이 불완전하므로 WebGL 2.0 via Three.js가 실용적 선택이다. 완화: 기기 능력 감지, 품질 티어, WebGL 불가 기기용 정적 폴백(포스터 이미지). 네 번째는 **VRAM 고갈**이다. 완화: VRAM 인식 스케줄링, 동적 모델 로딩/언로딩, 세마포 기반 동시성 제한. 다섯 번째는 **롱테일 생성 실패**다. 완화: 재시도 로직(지수 백오프), 429 레이트 리밋 및 5xx 일시 오류 처리, 우아한 성능 저하.

## 개발 로드맵

### Phase 1: MVP (4-6주)

**목표:** 단일 이미지 → 3D 모델 + 기본 뷰어로 핵심 가치 검증. **팀:** 3명 (Product Manager, Tech Lead, 1 Frontend Engineer). **기능:** 사진 업로드 및 품질 가이드, AI 기반 3D 변환(단일 이미지, 호스팅 API 사용), 기본 3D 뷰어(회전/줌), 3-5개 스타터 템플릿, 기본 커스터마이징(색상/텍스트/레이아웃), 공유 가능한 URL로 퍼블리시, 모바일 반응형 출력, 사용자 인증(이메일 + 소셜 로그인), 무료 티어(월 3회 변환). **기술:** Next.js + R3F + Three.js, FastAPI 백엔드, Meshy/Tripo API 통합, S3 스토리지, CDN. **검증 지표:** 활성화율(가입 후 첫 3D 모델 생성) **40%+**, 무료-유료 전환율 **3-5%**.

### Phase 2: v1 (8-12주)

**목표:** 멀티뷰 지원, 사용자 계정, 포트폴리오 에디터, 소셜 공유. **팀:** 5-7명 (2 Frontend/3D Engineers, 1-2 AI/ML Engineers, 1 Backend Engineer, 1 Product/Design Lead). **기능:** 멀티뷰 이미지 업로드(정확도 향상), AI 배경 제거, 커스텀 도메인 지원, 기본 분석(조회수/공유), 프리미엄 템플릿 마켓플레이스, GLB/USDZ보내기, 한국어 지원 및 로컬 로그인(Kakao/Naver). **기술:** 자체 호스팅 GPU 파이프라인(Hunyuan3D/TRELLIS.2), 비동기 잡 큐, 품질 스코어링 파이프라인. **검증 지표:** 월간 활성 사용자(MAU) **1,000+**, 유료 전환 **5%+**, 생성 성공률 **95%+**.

### Phase 3: v2 (16-24주)

**목표:** 실시간 협업, AI 기반 씬 구성, 모바일 AR, 마켓플레이스. **팀:** 8-12명. **기능:** 커리어 애니메이션(스크롤 기반 장면), 고급 커스터마이징(조명/카메라 경로/오디오), 팀 협업, API 액세스, 화이트라벨, 벌크 처리. **기술:** 고급 셰이더 파이프라인, 실시간 동기화, AR 지원. **검증 지표:** MAU **10,000+**, 기업 고객 **10+**, NPS **40+**.

## 팀 구성

### 핵심 팀 (5-7명)

**Frontend/3D Engineer 2명:** React/Three.js 전문가. 필수 역량: 탄탄한 JavaScript 기초, Three.js 씬 그래프 이해, 애니메이션/RAF 루프, GLTF/GLB 에셋 로딩, 성능 인식(드로콜 예산, 텍스처 크기, 모바일 제약). 시니어 요구 사항: 커스텀 GLSL 셰이더 작성, 포스트 프로세싱 파이프라인, 물리 엔진 통합, React Three Fiber, WebXR. **AI/ML Engineer 1-2명:** 3D 생성 모델 전문가. 필수 역량: PyTorch, 디퓨전 모델, CUDA, VRAM 최적화, 모델 서빙(vLLM/TensorRT). **Backend Engineer 1명:** FastAPI/인프라 전문가. **Product/Design Lead 1명:** 제품 기획 및 디자인 총괄.

### 채용 전략

Three.js 개발자 채용은 **일반 프론트엔드 경험으로 대체할 수 없다**. "시니어 프론트엔드 역할로 취급하는 것은 실수다. 강력한 React 개발자가 Three.js를 배울 수 있지만, 프로덕션 품질의 GPU 작업에 대한 램프업 시간은 주 단위가 아닌 월 단위로 측정된다" ([creativedevjobs.com](https://www.creativedevjobs.com/blog/how-to-hire-a-threejs-developer)). 채용은 입증된 3D 포트폴리오 작업을 일반 프론트엔드 경험보다 우선해야 한다. 인재 풀은 Three.js Journey(Bruno Simon), Wawa Sensei, Poimandres Discord(R3F/Drei 생태계) 커뮤니티에 집중되어 있다. AI/ML 엔지니어는 디퓨전 기반 생성 모델과 GPU 자원 관리 경험이 있어야 한다. 채용 일정은 소싱부터 오퍼까지 **8-12주**, 2-4주 사전 통보 기간을 고려해야 한다 ([digiqt.com](https://digiqt.com/blog/vuejs-hiring-roadmap/)).

| Phase 2: v1 | 8-12주 | 베타 출시, 사용자 계정, 자체 호스팅 전환 | 5-7명 |
| Phase 3: v2 | 16-24주 | 정식 출시, 커리어 애니메이션, 기업 기능 | 8-12명 |

### 주요 마일스톤

**1-2주:** 요구사항 정의, 기술 스택 확정, 디자인 시스템 기초 구축. **3-4주:** 3D 변환 파이프라인 프로토타입(Meshy/Tripo API 통합), 기본 3D 뷰어 개발. **5-6주:** 사용자 인증, 무료 티어, 퍼블리시 기능, 알파 테스트. **7-10주:** 멀티뷰 업로드, AI 배경 제거, 포트폴리오 에디터, 자체 호스팅 GPU 파이프라인 개발. **11-14주:** 한국어 지원, 로컬 로그인, 분석 대시보드, 베타 출시. **15-20주:** 커리어 애니메이션, 고급 커스터마이징, 팀 협업. **21-24주:** API 액세스, 화이트라벨, 기업 영업 시작, 정식 출시.

### 병렬 개발 전략

프론트엔드(포트폴리오 뷰어/에디터)와 백엔드(생성 파이프라인) 개발을 병렬화한다. 디자인 시스템 구축은 프론트엔드 개발과 동시에 진행하여 컴포넌트 재사용성을 확보한다. AI/ML 파이프라인은 MVP 단계에서 호스팅 API로 시작하여 v1 단계에서 자체 호스팅으로 전환하므로, 백엔드 팀은 초기부터 GPU 인프라 설계를 준비해야 한다.

## 결론

3D 포트폴리오 서비스 구축은 **기술적 실행 가능성과 시장 기회의 교차점**에 위치한다. AI 3D 생성 기술이 **$0.18-0.25/모델**로 생산 준비 수준에 도달했고, 포트폴리오 빌더 시장이 **102억 달러** 규모로 성장하고 있지만, "사진-3D-애니메이션 포트폴리오" 서비스를 제공하는 주요 플레이어는 없다. 성공의 핵심은 3D 생성 자체(이미 상품화되고 있음)가 아니라 **자동 정리, 애니메이션, 프레젠테이션 계층**에 있다. $0.20 AI 모델과 프로페셔널 포트폴리오 사이에 있는 **$80-350의 수동 작업**을 자동화하는 것이 본 서비스의 핵심 차별화 포인트다. 한국 시장은 **35만 명의 디자이너**, **30.5% CAGR의 크리에이터 경제**, 그리고 3D 포트폴리오 빌더의 완전한 부재라는 최적의 테스트베드를 제공한다. API-first 전략으로 시작하여 빠르게 검증하고, 사용자 기반이 확보되면 자체 호스팅으로 전환하여 단위 경제성을 개선하는 것이 권장 경로다. 5% 월간 이탈률과 $50-100 CAC에서 LTV:CAC **3.8-7.6:1**, 약 2개월의 CAC 회수 기간은 수익성 있는 비즈니스로의 명확한 경로를 시사한다.
